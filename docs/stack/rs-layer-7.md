# 第 7 层：排序服务

排序服务要在几十毫秒内给几百到上万个候选打分：粗排用轻模型从上万筛到几百，精排用最重的多任务模型给几百个候选算分。瓶颈常常不在矩阵乘，而在取特征、查 embedding 和网络往返；算力要按「峰值 QPS × 每请求候选数」来备。

- **多阶段漏斗**：每一级的截断数和延迟预算一起定，召回多路并行，排序各级串行。
- **在线特征**：用户侧每请求取一次，物品侧取 $m$ 次，靠批量读和本地缓存压延迟。
- **排序推理**：请求内的候选天然是一个 batch，跨请求再攒 batch；TB 级 embedding 拆成独立服务。
- **缓存 / 降级**：特征超时用默认值；过载时先减候选数、关掉重模块，最后才拒绝请求。
