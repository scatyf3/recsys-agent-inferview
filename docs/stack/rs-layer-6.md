# 第 6 层：召回

召回要在十毫秒量级里，从千万到十亿级的候选池里捞出几千到上万个候选。打分模型只能是「用户侧和物品侧分开算」的结构：物品向量离线算好建索引，线上每个请求只算一次用户向量，再做近似最近邻检索。这一层的取舍是召回率、延迟、内存和索引新鲜度之间的交换。

- **双塔**：放弃用户和物品的交叉特征，换来物品向量可以缓存；in-batch 负样本要做 logQ 校正。
- **ANN 索引**：HNSW 召回高、内存大；IVF-PQ 把每条向量压到十几字节，再用原始向量重排补精度。
- **GPU 检索 / 向量库**：大 batch 查询和暴力检索适合 GPU，图遍历不适合；线上还要处理分片、实时插入和过滤。
