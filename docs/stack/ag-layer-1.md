# 第 1 层：上下文

上下文窗口是 agent 的工作内存，也是账单的主体：agent 任务的输入 token 通常是输出的上百倍，每轮都要把前面的内容再付一次钱。这一层管窗口里放什么、按什么顺序放、满了怎么办。核心权衡是信息量对成本和缓存：放得越多模型看到的越全，但每轮都更贵，模型也更容易在长上下文里漏信息；删改历史能省 token，却会打断 prompt cache 的前缀，下一轮要按写入价重付。

- **token 预算**：系统提示、工具定义、历史、工具结果各占多少，留多少给输出。
- **prompt caching**：稳定前缀、只追加，让每轮的输入大部分按缓存读取价计费。
- **压缩 / 摘要**：上下文快满时清掉旧工具结果或整体摘要，或者把子任务交给 sub-agent。
