# 第 0 层：模型推理

Agent 的推理请求和聊天不一样：一个任务几十轮，每轮的输入是上一轮的全部上下文再加几百到几千个新 token，输出却只有几百个，中间还夹着秒级到分钟级的工具执行。这一层管的是推理服务怎么适应这种负载：前缀的 KV 能不能复用、工具执行期间 KV 留在哪、同一个任务的后续轮次发到哪台机器、工具调用的格式怎么保证合法。核心权衡是显存对重算：KV 留得越久，命中越高、TTFT 越低，但占住的 HBM 越多，能并发的请求越少。

- **prefix cache / KV 复用**：按 block hash 或 radix tree 匹配前缀，命中的部分不用重算。
- **TTFT 与长 prefill**：每轮的首 token 延迟取决于没命中的那一段有多长。
- **约束解码**：用 grammar 生成 token mask，保证工具调用参数是合法 JSON。
- **session 亲和路由**：同一个任务的请求尽量回到存着它 KV 的那台机器，同时不能把一台压垮。
